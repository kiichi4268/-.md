# 📲 LINE（エルメ）申込受付・デジタル参加証 自動発行 仕様書

Google フォームや手動 DM をやめ、**LINE のトーク画面の中だけで「タップで選ぶ → 回答 → 参加証が即届く」**受付を、エルメ（L Message）で組むための仕様書です。

- 対象: LINE公式アカウント（無料のコミュニケーションプラン）＋ エルメ（フリープランを前提）
- 連動: タグ名は `data/events.csv` の `event_id` と揃え、申込数・初参加・一人参加の集計にそのまま使う（フェーズ1）
- 担当AI: 📈 マーケターAI（文言）／🔍 品質管理AI（参加証の記載内容チェック）

> ⚠ エルメの画面名・ボタン名・無料プランで使える機能の範囲は変わることがあります。本書は **機能の組み合わせ方（設計）** を正とし、画面上の名称は管理画面の表示に読み替えてください。「要確認」と書いた箇所は、本番前に「7. 公開前テスト」で必ず確かめてください。

## 1. 設計の核心：月200通の上限を「応答」で回避する

### LINE の通数ルール
| 送り方 | 例 | 通数カウント |
|---|---|---|
| **応答（返信）メッセージ** | ユーザーがメッセージ送信・ボタンをタップした**直後**に返す自動応答 | **カウントされない（無料）** |
| **プッシュ（配信）メッセージ** | 一斉配信、セグメント配信、ステップ配信、リマインド、Webフォーム送信後の自動送信 | **カウントされる**（1回の送信 × 受信人数。吹き出し数は問わない） |

LINE の応答メッセージは、ユーザーからのアクション（メッセージ送信・ボタンタップ・友だち追加）を受けた直後に返すときだけ使えます。
したがって、**ユーザーのタップを起点にすべての受付を進めれば、申込〜参加証の発行までの通数を0にできます。**

### このため本仕様では
1. **アンケートは Web の回答フォームではなく、トーク内のボタンで聞く**（1問＝1タップ。タップのたびに応答で次の質問を返す）
2. 自由記述（本名など）がどうしても必要な場合のみ回答フォームを使う。その場合も、**フォーム送信後に自動送信はせず**、完了画面で「LINE に戻って『参加証を表示』をタップしてね」と案内し、タップに対する応答で参加証を返す
3. プッシュ通数は「前日リマインド」など効果の大きい用途に限定して使う（「5. 通数の試算」参照）

> **要確認**: エルメのボタンアクション（タグ付け＋テンプレート送信など）や友だち追加時のあいさつが、内部で「応答」として送られているかどうか。「7. 公開前テスト」の通数確認テストで、LINE公式アカウントの管理画面（ホーム → 今月のメッセージ利用状況）の数字が増えないことを確かめてから公開してください。

## 2. 全体フロー

```
[Instagram等のプロフィールリンク]
        ↓ 友だち追加
① あいさつ（応答）……「イベントに申し込む」ボタン付き
        ↓ タップ
② 開催予定カルーセル（応答）……1イベント1枚。画像・日時・会場・参加費・「申し込む」ボタン
        ↓ タップ（タグ: evt_<event_id> を付与）
③ Q1「参加は初めてですか？」[はい][いいえ]（応答）……タグ: first_timer / repeater
        ↓ タップ
④ Q2「お一人での参加ですか？」[一人][友だちと]（応答）……タグ: solo / group
        ↓ タップ
⑤ Q3「ラケット（用具）は借りますか？」[借りる][持参]（応答）……タグ: rental / own_gear
        ↓ タップ
⑥ 🎫 デジタル参加証（応答）……画像＋テキスト。当日は受付でこの画面を見せるだけ

いつでも: リッチメニュー「参加証を表示」→ 付いているタグに応じて参加証を再表示（応答）
```

1回の申込にかかるタップは **4回（②〜⑤）**、所要時間は約20秒です。

## 3. 事前準備

### 3-1. タグ設計（`data/events.csv` と対応）
| タグ | 付けるタイミング | 用途 |
|---|---|---|
| `evt_<event_id>`（例: `evt_2026-10-17_volleyball_shinjuku`） | ② の「申し込む」 | 申込数（`applied`）・参加証の出し分け |
| `first_timer` / `repeater` | ③ | 初参加数（`first_timer`） |
| `solo` / `group` | ④ | 一人参加数（`solo`） |
| `rental` / `own_gear` | ⑤ | 用具の準備数 |
| `canceled_<event_id>` | キャンセル時 | キャンセル数の把握（`evt_` タグは外す） |
| `attended` | 開催後（主催者が手動） | リピート施策・協賛提案の参加者データ |

> `first_timer` などはイベントごとに変わるため、**集計時は `evt_<event_id>` との掛け合わせ（AND 絞り込み）**で数えます。2回目以降の申込では、③ で `repeater` を選んだ時点で `first_timer` タグを外すアクションを入れてください。

### 3-2. 素材
| 素材 | 仕様 | 作り方 |
|---|---|---|
| カルーセル画像（イベントごと） | 1枚、横長比率（例: 1040x585） | 🎨 デザイナーAI のカルーセル表紙を流用（Canva でリサイズ） |
| 参加証画像（イベントごと） | 縦長（例: 1040x1300）。種目・日付・会場・「受付でこの画面を見せてね」 | Canva テンプレートを1つ作り、イベントごとに文字だけ差し替え |
| リッチメニュー画像 | 2500x1686（6分割） | 下記レイアウトで1枚 |

### 3-3. リッチメニュー（6分割）
| 左上 | 中央上 | 右上 |
|---|---|---|
| 🏸 **イベントに申し込む** → キーワード「申し込む」を送信 | 🎫 **参加証を表示** → キーワード「参加証」を送信 | 📅 **開催予定** → キーワード「日程」を送信 |
| **よくある質問** → キーワード「FAQ」を送信 | **キャンセル・変更** → キーワード「キャンセル」を送信 | **Instagram** → プロフィールURLを開く |

> ボタンはすべて「テキスト（キーワード）を送信」にするのがポイントです。ユーザーが送信した扱いになるため、続く自動返信が応答になります。

## 4. 構築手順

### Step 1. 友だち追加時のあいさつ
- 内容: 「友だち追加ありがとうございます！参加者の8割がお一人様の、ゆるいスポーツ会です🏸」＋ボタン［イベントに申し込む］［日程を見る］
- ボタンのアクション: キーワード「申し込む」「日程」を送信
- **ステップ配信（追加後○日に自動送信）は設定しない**（プッシュになり通数を消費するため）

### Step 2. 開催予定カルーセル（キーワード「申し込む」「日程」に自動応答）
- エルメのカルーセル（またはフレックス）メッセージを作成し、`status: open` のイベントを1枚ずつ並べる（最大10枚）
- 各カードの記載: 画像／`{{sport}}`会 `{{date}}({{weekday}})` `{{start}}〜`／`{{area}}`／参加費`{{fee}}`円
  - 枠数の書き方は `prompts/fill_capacity_template.md` の判定表に従う（充足率が低いうちは「残り◯枠」を出さない）
- ボタン［申し込む］のアクション:
  1. タグ `evt_<event_id>` を付与
  2. Step 3 の質問テンプレート（Q1）を送信
- 満員のイベントはカードを外すか、ボタンを［キャンセル待ちで登録］に差し替え（タグ `wait_<event_id>`）

### Step 3. 1タップ回答（Q1〜Q3）
それぞれボタン型メッセージ（テキスト＋ボタン2つ）で作成し、ボタンのアクションで「タグ付与 → 次の質問を送信」をつなぐ。

| 質問 | ボタンA（アクション） | ボタンB（アクション） |
|---|---|---|
| Q1 参加は初めてですか？ | はい → `first_timer` 付与 → Q2 | いいえ → `repeater` 付与・`first_timer` 解除 → Q2 |
| Q2 お一人での参加ですか？ | 一人です → `solo` 付与 → Q3 | 友だちと → `group` 付与 → Q3 |
| Q3 用具は借りますか？ | 借りる → `rental` 付与 → 参加証 | 持参する → `own_gear` 付与 → 参加証 |

- 質問文の下に一言の安心材料を添える（例: Q1「前回は初参加の方が◯割でした。安心してね」※◯には `data/events.csv` の実績値を入れる。実績が無ければ数値は書かない）
- 種目に用具が要らない場合（カレー会など）は Q3 を省き、Q2 から直接参加証へ

### Step 4. デジタル参加証（応答で即時発行）
イベントごとに「参加証テンプレート」を1つ作り、Q3 のボタンアクションと Step 5 の再表示から呼び出す。

**画像**: 3-2 の参加証画像

**テキスト**（友だち情報の差し込みで表示名を入れる。差し込みはエルメの編集画面の差し込みボタンから選択）:
```
🎫 参加証｜Macachette Sports
━━━━━━━━━━━━
{LINE表示名} さん、お申込みありがとうございます！

🏐 {{sport}}会
📅 {{date}}({{weekday}}) {{start}}〜{{end}}
📍 {{venue}}（詳しい場所は前日までにこのトークでお知らせします）
💰 参加費 {{fee}}円（当日現金／PayPay）← 支払い方法は実際の運用に合わせて修正
🎒 持ち物：室内用シューズ・飲み物・タオル

✅ 当日は受付でこの画面を見せるだけでOK
🔰 初めての方・お一人の方が多いので、気軽に来てね

変更・キャンセルはメニューの「キャンセル・変更」から
━━━━━━━━━━━━
```

> 🔍 品質管理AI チェック: 日付と曜日の一致／会場・参加費・支払い方法が実際の運用と一致しているか／`{{…}}` が残っていないか。

### Step 5. 「参加証を表示」（キーワード「参加証」に自動応答）
- 条件分岐（タグによる出し分け）で、付いている `evt_<event_id>` ごとの参加証テンプレートを返す
- `evt_` タグが1つも無い場合: 「まだお申込みがないみたい。メニューの『イベントに申し込む』からどうぞ」＋Step 2 のカルーセル
- 複数のイベントに申込済みの場合: それぞれの参加証を続けて返す（1回の応答で送れる吹き出しは最大5つまで）

> **要確認**: 自動応答の条件分岐（タグ条件）がエルメの無料プランで使えるか。使えない場合は、イベントごとに「参加証1017」のような専用キーワードを作り、Step 4 の参加証の最後に「再表示はこのトークで『参加証1017』と送ってね」と書く運用で代替します。

### Step 6. キャンセル・変更（キーワード「キャンセル」に自動応答）
1. 申込中のイベントをボタンで表示（Step 5 と同じタグ条件）
2. ［キャンセルする］→ `evt_<event_id>` を外し `canceled_<event_id>` を付与 →「キャンセルを受け付けました。またの参加をお待ちしています」
3. 主催者への通知: エルメの管理者通知（設定がある場合）をオンにするか、毎日の集計（Step 7）で確認

### Step 7. 集計（`data/events.csv` への反映）
- エルメの友だちリストでタグを掛け合わせて絞り込み、人数を `data/events.csv` に転記する

| `events.csv` の列 | 絞り込み条件 |
|---|---|
| `applied` | `evt_<event_id>` |
| `first_timer` | `evt_<event_id>` AND `first_timer` |
| `solo` | `evt_<event_id>` AND `solo` |

- 頻度の目安: 開催14日前・7日前・3日前（枠埋め投稿のタイミングと同じ）
- **個人を特定できる情報（表示名・回答内容）は GitHub に保存しない**。`events.csv` には人数だけを書く

## 5. 通数の試算（無料プラン月200通）

### 応答で完結する（0通）
友だち追加あいさつ／カルーセル／Q1〜Q3／参加証の発行・再表示／FAQ／キャンセル

### プッシュになる（通数を消費する）
| 用途 | 1か月あたりの通数 | 判断 |
|---|---|---|
| 前日リマインド（会場の詳細・当日の連絡先） | 参加者数と同じ（例: 月90名 → 90通） | **推奨**。ドタキャン防止効果が最も大きい |
| 開催後のお礼＋次回案内 | 参加者数と同じ（90通） | 余裕がある月のみ。Instagram の開催レポで代替可 |
| 新イベントの一斉配信 | **友だち全員の人数**（例: 300名 → 300通） | 無料プランでは不可。下記の代替策を使う |
| キャンセル待ちへの空き連絡 | 該当者数（数通） | 推奨 |

**月90名規模の目安**: リマインド90通＋空き連絡10通 ≒ **100通**。無料枠内に収まります。

### 一斉配信の代わりに使う方法（0通）
- 新イベントはリッチメニュー「開催予定」とカルーセルを更新するだけにして、告知は Instagram・Threads・ストーリーズで行う（「LINEのメニューから申し込めます」）
- リマインドの文面に「次回の日程はメニューの『開催予定』からどうぞ」を入れる（同じ1通の中なので追加の通数はかからない）
- 吹き出しを分けて送らず、1回の送信にまとめる（同じ1通として数えられる）

### 有料プランへの切り替え目安
- 「リマインド＋お礼＋一斉配信」が毎月200通を超える状態が2か月続いたら、ライトプランへの切り替えを検討します（月20万円の売上に対して固定費として妥当な範囲。**最新の料金は LINE 公式サイトで要確認**）
- 📊 アナリストAI の週次レポートで、LINE の今月の利用通数を確認項目に入れる

## 6. 回答フォームを併用する場合（自由記述が必要なとき）
本名・緊急連絡先などを集める必要がある大会形式のイベントのみ、エルメの回答フォームを使います。

1. Step 3 の Q3 の後に「最後に、お名前だけ教えてね（30秒）」＋フォームURLのボタン
2. フォームの回答で友だち情報（お名前など）を保存し、タグ `form_done_<event_id>` を付与
3. **フォーム送信後の自動メッセージ送信はオフにする**（プッシュになるため）
4. 完了画面の文言:「回答ありがとうございます！LINE に戻ってメニューの『参加証を表示』をタップしてね」
5. フォームの冒頭に、個人情報の利用目的（イベント運営・連絡のみに使用）を書く

## 7. 公開前テスト（チェックリスト）

### 通数確認テスト（最重要）
1. LINE公式アカウントの管理画面で「今月のメッセージ利用状況」の数字を控える
2. テスト用の LINE アカウントで、友だち追加 → 申込（Q1〜Q3）→ 参加証表示 → キャンセルまで一通り操作する
3. 数分後に利用状況を再確認する
   - **増えていない** → 設計どおり応答で送られています。公開OK
   - **増えている** → どの操作で増えたかを1つずつ切り分け、その箇所をキーワード送信起点（応答）に作り替える

### 動作テスト
- [ ] リッチメニューの6ボタンがすべて反応する
- [ ] カルーセルのイベント・日付・曜日・参加費が `data/events.csv` と一致している
- [ ] Q1〜Q3 のボタンで正しいタグが付く（友だちリストで確認）
- [ ] 2回目の申込で `first_timer` が外れ、`repeater` が付く
- [ ] 参加証に表示名が差し込まれ、`{{…}}` が残っていない
- [ ] 「参加証」と送ると、申込済みのイベントの参加証だけが出る／未申込なら案内が出る
- [ ] キャンセル後に `evt_` タグが外れ、「参加証」と送っても出ない
- [ ] 満員のイベントのカードが外れている、またはキャンセル待ちボタンになっている

## 8. イベントごとの運用手順（毎回5分）
1. `data/events.csv` に行を追加
2. Canva で参加証画像とカルーセル画像の文字を差し替え
3. エルメでカルーセルにカードを1枚追加し、参加証テンプレートを複製して日付・会場を差し替え
4. 開催14日前・7日前・3日前にタグを集計して `events.csv` を更新 → `prompts/fill_capacity_template.md` の判定表でパターンを選んで SNS 投稿
5. 前日にリマインド（`evt_<event_id>` のタグで絞り込んで配信）
6. 開催後、参加者に `attended` を付与し、カードを外す
